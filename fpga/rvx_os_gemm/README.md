# rvx_os_gemm

RISC-V SoC (RVX) with the URSA systolic array accelerator on FPGA, targeting
the ZedBoard (`xc7z020clg484-1`).

The RVX core runs in the PL and talks to URSA over AXI4-Lite. Its 40 MHz clock
comes from the PS, so the ARM must be initialized for the RISC-V to run.

## Layout

```
rvx_os_gemm/
├── driver/         firmware running on the RVX (C/C++, CMake)
│   └── ursa_cnn/   CNN application + URSA driver
├── firmware/run/   scripts to merge the ELF into the bitstream and program via JTAG
├── vivado_proj/    hardware sources
│   ├── rtl/        SoC Verilog (rvx_zynq, rvx_soc_axi, core, peripherals)
│   ├── bd/         block designs as Tcl (bd_zynq, bd_ursa)
│   ├── ip_repo/    URSA IP generated by HLS
│   ├── constraints/ ZedBoard XDC
│   ├── mem/        .mem files for RAM initialization
│   ├── scripts/    create_project.tcl and 01_create_project.sh
│   └── build/      generated project (not versioned)
└── third_party/    libsteel
```

Everything that is a source lives in the repository. The `build/` directories
are disposable and can be deleted at any time.

## Full flow

### 1. Create the Vivado project

```bash
cd vivado_proj
./scripts/01_create_project.sh --run
```

Without `--run` it only creates the project; with `--run` it also runs synthesis
and implementation through bitstream generation. The project lands in
`vivado_proj/build/rvx-ursa/`.

### 2. Build the firmware

```bash
cd driver/ursa_cnn
./do-cmake-generate-build.sh
cd build && make
```

Produces `driver-ursa.elf`. Check the size report to confirm the binary fits in
the 128 KB of RAM.

### 3. Generate the MMI (whenever implementation changes)

The MMI maps BRAM bit lanes for `updatemem`. It depends on placement, so it must
be regenerated every time implementation is re-run. See `firmware/run/README.md`.

### 4. Merge the firmware into the bitstream

```bash
cd firmware/run/build
../12_merge_bit.sh
```

Produces `rvx_zynq_driver-ursa.bit`. Repeat this step after every firmware
change — no re-synthesis needed.

### 5. Program the board

```bash
cd firmware/run
./03_program_online_jtag.sh build/rvx_zynq_driver-ursa.bit
```

## Board connections

| What | Where |
|---|---|
| JTAG | `PROG` micro-USB (J17) |
| ARM serial | `UART` micro-USB (J14) → `/dev/ttyACM0` |
| RVX serial | Pmod JA, pins 1 (TX), 2 (RX) and GND → 3.3 V USB-serial adapter |

Both serials at 115200 8N1.

LEDs: LD0 is a 1 Hz tick (core alive), LD1 GPIO, LD2 UART TX, LD3 UART RX.

## Address map

| Region | Base |
|---|---|
| RAM (128 KB) | `0x0000_0000` |
| UART | `0x8000_0000` |
| MTIMER | `0x8001_0000` |
| GPIO | `0x8002_0000` |
| URSA (over AXI) | `0x4000_0000` |

Inside the URSA window: `s_axi_ap` at `0x4000_0000`, `s_axi_control` at
`0x4001_0000`, and the `aw`, `bi` and `ca` BRAMs at `0x4002_0000`,
`0x4003_0000` and `0x4004_0000`.

## Requirements

- Vivado 2023.2
- RISC-V rv32i toolchain (`riscv32-unknown-elf-`)
- CMake 3.15+
- Python 3 with PyYAML
