# gen_bench.py

Generates the GEMM benchmark suite used to exercise URSA.

The script writes two files: a header with the case descriptors and a payload
with the matrix data. Small cases carry their matrices literally. Large ones do
not: they are regenerated on the target by a deterministic PRNG that is
replicated bit for bit in C, so the header only needs to store a seed and a
checksum. This keeps the suite small enough to fit on the board.

## Dimensions

Matrices follow the same convention as `mxm_execute_ursa`:

| Matrix | Shape |
|--------|-------|
| A      | P x M |
| B      | M x Q |
| C      | P x Q |

`M` is the reduction depth, so every element of C is a sum of M products.

## Usage

```bash
python3 gen_bench.py --outdir ./bench/uniform  --acc-bits 20 --auto-range --literal-max 32 --pattern uniform
python3 gen_bench.py --outdir ./bench/identity --acc-bits 20 --auto-range --literal-max 32 --pattern identity
python3 gen_bench.py --outdir ./bench/constant --acc-bits 20 --auto-range --literal-max 32 --pattern constant
```

Each run produces `ursa_bench.h` and `ursa_bench_data.cpp` in the output directory.

## Options

| Option | Meaning |
|--------|---------|
| `--outdir` | Where to write the two generated files. |
| `--pattern` | `uniform`, `identity` or `constant`. See below. |
| `--acc-bits` | Accumulator width assumed by the golden reference. Must match `macc_t` in the synthesized design. |
| `--auto-range` | Cap the input magnitudes per case so the accumulator can never overflow. |
| `--literal-max` | Largest dimension still written out as literal data. Anything above is regenerated by the PRNG. |
| `--max-m` | Drop cases whose reduction depth M exceeds this value. |
| `--range-a`, `--range-b` | Manual magnitude caps, when `--auto-range` is not used. |
| `--seed` | Base seed. Changing it changes every case. |
| `--dtype-a`, `--dtype-b`, `--dtype-c` | Element types. Must mirror `settings.h`. |

### Why `--acc-bits` matters

The reference wraps the accumulator after every MAC, exactly like the PE does.
If the value here does not match the hardware, the golden checksums describe a
machine that does not exist and every case will appear to fail on the board.

Note that `macc_t` is `int32_t` outside `__SYNTHESIS__`, so C simulation does
not model the narrow accumulator. Only the generated reference does.

### Why `--auto-range`

At 20 bits with full-range inputs, 16 of the 40 cases overflow the accumulator.
Those cases still produce valid golden values, but they measure saturation
rather than arithmetic. `--auto-range` derives a magnitude cap per case from
`--acc-bits` and M, so overflow becomes impossible by construction.

Running without the flag is useful once: the report shows exactly at which M
the accumulator starts to saturate.

## Patterns

The three patterns are not variations of the same test. Each answers a
different question, and they are meant to be run together.

### uniform, the experiment

A and B hold random values across the full permitted range. This is the
realistic case: every element of C is a sum of M different products, with no
structure to exploit.

This is the baseline because a bit flip in a PE propagates into the accumulator
and survives to the output, since nothing cancels it. It is the condition of
maximum SDC observability, so the cross section measured here is the highest
one obtainable, and therefore the most conservative to report.

### identity, the diagnostic

A is the identity matrix and B is random. Since I·B = B, the expected result is
simply C = B.

This means the correct result is known without trusting any reference chain. If
C[i][j] differs from B[i][j], the corrupted element is immediately identifiable,
and its position points at which PE or which data path failed.

More importantly, it separates SDC from SEFI. A result that is entirely wrong,
or an accelerator that hangs, indicates a functional failure: control logic,
state machine, DMA. A result that is almost entirely correct with a few altered
elements indicates data corruption. With uniform data that distinction is hard
to draw. With the identity it is immediate.

One caveat: because A holds only ones and zeros, most MACs are multiplications
by zero. This lowers switching activity in the array, so the cross section here
is not comparable to the uniform one. Use this pattern to understand the
mechanism, not to measure a rate.

### constant, the negative control

A is all ones and B is all ones, so every element of C is exactly M.

This is the case of maximum arithmetic masking. All values are identical, so
many bit flips either produce results that still look plausible or are absorbed
by the regularity. The cross section here should be the lowest of the three.

Its scientific value is being the floor. If SDC shows up in the constant
pattern at the same rate as in the uniform one, something is wrong with the
measurement: the failure is not coming from the data but from something
structural, such as a configuration register, a loop counter or an address
pointer. This is the case that validates the methodology itself.

It is also where a control error stands out most clearly, precisely because the
data generates no noise.

## Verifying the suite

The suite is self checking. Regenerating from the same seed produces
byte identical files, and the runner recomputes every case in software and
compares against the golden checksum. A mismatch on the host means the
generator and the C-side PRNG have diverged. A mismatch on the board, with the
host passing, means the hardware.
