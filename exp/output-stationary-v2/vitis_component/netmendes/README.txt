URSA hardware tests -- LASCAS-2027 grid, General and Satellite datasets
=======================================================================

The networks of the LASCAS-2027 Gemmini experiments, on URSA: MiniViT
micro/tiny/small/base and the parameter-matched ("ViT-matched") ResNet18 and
VGG16 micro/tiny/small baselines, on the General (CIFAR-10, CIFAR-100,
ImageNet-1k) and Satellite (PatternNet, RESISC45) datasets. MiniViT on
ImageNet-1k and RESISC45 is base only, as in the paper; there are no ImageNet
CNN baselines. The tests are in general/ and satellite/.

CIFAR tests keep the paper's images (1024 for MiniViT micro/tiny/small, 512
otherwise), so "URSA host top-1" compares directly with "LASCAS spike INT8".
The 224/256-px datasets carry the first 32 of those images (the exporter's
seeded sample is a prefix), so their accuracy is not comparable to n=512/1024
-- these tests are about bit-exactness and timing. (The generated code
truncates percentages to two decimals where the paper rounds: 879/1024 prints
85.83% here and 85.84% there -- the same count.)

RESISC45 CNNs: configs/experiments/{resnet18,vgg16}_resisc45/exp0.py now pin
IMAGE_SIZE = 224, the resolution the loader trained and exported them at; they
used to inherit the dataset's native 256, so code generation traced the
networks at 256x256 and read the 224x224 images with the wrong geometry. That
is what the LASCAS spike sweep measured as an INT8 "collapse" for VGG16 on
RESISC45 (6.64 / 3.90 / 2.53% against 77-88% FP32; the LASCAS column below
still shows those numbers), and it is gone here. ResNet18 and VGG16-small on
PatternNet and ResNet18 on RESISC45 had no LASCAS hardware result (their
exports or builds failed then); they were exported now, 32 images each.
Every generated file now checks at compile time that the embedded images
match the geometry the network was traced at.
One self-contained, self-checking program per network, generated by
src/codegen (backend "ursa") in ViT-Research, branch ARC-2027. Each file holds
the network, its int8 weights and scales, the test images and labels, and the
int8 logits the bit-exact host model of URSA computes for every image.

Running one
-----------
1. In vitis_component/cnn-sat-6/src, set tb_main.cpp, cnn_conv_engine.cpp and
   the weight/image tables (cnn_weights_*.cpp, cnn_eval_images_*.cpp) aside
   and copy in ONE *_hwtest.cpp. The test needs only platform.cpp/.h,
   ursa.cpp/.h, utils.cpp/.h, lscript.ld and the Vitis CMake files.
   (Or, from ViT-Research: scripts/ursa_build_app.sh -s 8 -l bram <file>.)
2. Build as usual: -DSA_SIZE=<n> and -DBRAM / -DOCM / -DHYBRID, matching the
   bitstream. -DUSE_ARM gives the software-GEMM (CPU only) baseline of the
   same network. -DURT_MAX_IMAGES=8 runs only the first 8 images.
3. Expected on the UART, at the end:
       [urt] golden check: N/N images bit-exact
       URT HW TEST PASS
   A difference prints the image, the first differing class and both logit
   rows (first 4 differing images), and the run ends with URT HW TEST FAIL.
   main() returns 0 only on PASS.

Every run also prints the per-layer plan (reduction chunks and URSA call
shape), the per-layer time profile, and the stage split per inference:
lowering (im2col/transpose), transfer (A/B into BRAM, C out, cache
maintenance), gemm (the URSA call including polling), epilogue
(requantization), and everything else on the ARM. Times come from the
Cortex-A9 global timer at CPU/2 ("[urt] timer: N ticks/s").

The expected logits do not depend on SA_SIZE, the memory layout or the engine,
so every file serves every bitstream of the sweep. They do assume the default
accumulator guard; building with -DURT_ACC_GUARD=0 (cnn-sat-6's unguarded
chunking) warns at compile time, and the transformer tests are then expected
to fail the golden check.

"URSA host top-1" is the accuracy the bit-exact model of the IP reaches on
the embedded images. All 20 CIFAR networks reproduce their LASCAS spike INT8
result exactly (same header, same images). For the 32-image 224/256-px tests
the LASCAS column is for n=512/1024 and not comparable -- except the VGG16
RESISC45 cells, whose LASCAS values are the geometry bug described above.
"wraps" counts host-model accumulator overflows with the guard on, which must
be 0. ELF sizes are from an SA_SIZE=8 BRAM build against
platform-ursa-vanilla-bram.
